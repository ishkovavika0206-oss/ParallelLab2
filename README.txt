ЛАБОРАТОРНАЯ РАБОТА 2: КОНВЕЙЕР + НОД

Назначение
Программа читает пары целых чисел из файла, вычисляет их НОД алгоритмом
Евклида и записывает исходные числа и НОД в выходной файл.
Используется C++17 и std::thread. Библиотека pthread не требуется.

Состав конвейера
1. readTasks: читает input.txt и помещает пары в ограниченную очередь Q1.
2. calculateResults: берёт пары из Q1, вычисляет НОД и помещает записи в Q2.
3. writeResults: берёт записи из Q2 и записывает их в выходной файл.
Основной поток открывает файлы, создаёт очереди и три рабочих потока,
затем дожидается всех через join. Всего с основным — четыре потока.

Очереди защищены мьютексами. Условная переменная используется для ожидания
данных и свободного места. При закрытии очередь отдаёт оставшиеся записи.
После конца входного файла читатель закрывает Q1 и входной файл;
вычислитель обрабатывает остаток Q1 и закрывает Q2;
писатель обрабатывает остаток Q2 и закрывает выходной файл.
Обработка чисел и задержки выполняются вне мьютексов очередей.
При ошибке отменяются обе очереди, ожидающие потоки пробуждаются.
Ошибка передаётся в основной поток после join; файл может быть неполным.

Файлы
main.cpp — весь исходный код.
ParallelLab2GCD.sln и ParallelLab2GCD.vcxproj — проект Visual Studio 2022.
input.txt — 20 пар для демонстрации.
expected_output.txt — ожидаемые ответы для этого input.txt.
CMakeLists.txt — альтернативная сборка через CMake.

Вход
Одна пара на строку: a b. Пустые строки пропускаются.
Допущение реализации: целые неотрицательные числа от 0 до
18446744073709551615 включительно. Пара 0 0 запрещена;
НОД(0,b)=b и НОД(a,0)=a для ненулевого второго числа.
Некорректная строка, отрицательное число и переполнение вызывают ошибку
с номером строки. Допускаются UTF-8 BOM и окончания строк Windows.
Для демонстрации достаточно готового input.txt; менять числа не требуется.

Выход
Одна строка на задачу: a b НОД(a,b).
Например: 18 24 6.
Порядок строк совпадает с порядком исходных пар.
Выходной файл выбранного режима перезаписывается при каждом запуске.

ЗАПУСК В VISUAL STUDIO 2022
1. Полностью распаковать архив, например в C:\Labs\ParallelLab2GCD.
   Не открывать проект непосредственно внутри ZIP.
2. Открыть ParallelLab2GCD.sln.
3. Если Visual Studio предлагает установить средства C++:
   установить рабочую нагрузку «Разработка классических приложений на C++»
   с MSVC v143 и Windows SDK.
4. Выбрать Release и x64. Нажать Ctrl+Shift+B, затем Ctrl+F5.
5. В первом запросе нажать Enter: используется input.txt из папки проекта.
6. Ввести режим, при необходимости задержку, затем ёмкость очередей.
   Каждый ответ подтверждать Enter.

В готовом проекте уже установлены C++17, /utf-8 и рабочая папка $(ProjectDir).
Файлы input.txt и main.cpp находятся рядом с .vcxproj.
Программа печатает текущую рабочую папку и полный путь к результатам.
Файл результата открывается Блокнотом через Проводник.

Если создаёте проект вручную:
- создать пустой консольный проект C++;
- добавить main.cpp (готовый шаблонный файл с другим main удалить);
- C/C++ -> Язык -> Стандарт языка C++: ISO C++17;
- C/C++ -> Командная строка -> Дополнительные параметры: /utf-8;
- C/C++ -> Предкомпилированные заголовки: Не использовать;
- Отладка -> Рабочий каталог: $(ProjectDir);
- положить input.txt в папку с .vcxproj.

ТРИ ОБЯЗАТЕЛЬНЫЕ СИТУАЦИИ
Во всех запусках использовать один и тот же input.txt, задержку 50 мс
и ёмкость каждой очереди 4. Отличается только замедленный этап.

Ситуация 1 — медленное чтение:
  имя файла: Enter
  режим: 1
  задержка: 50
  ёмкость: 4
  результат: output_read.txt
  Вычислитель ожидает пары; писатель ожидает результаты.

Ситуация 2 — медленное вычисление:
  имя файла: Enter
  режим: 2
  задержка: 50
  ёмкость: 4
  результат: output_compute.txt
  Q1 заполняется, читатель ожидает свободного места.
  Писатель периодически ожидает результаты вычисления.

Ситуация 3 — медленная запись:
  имя файла: Enter
  режим: 3
  задержка: 50
  ёмкость: 4
  результат: output_write.txt
  Q2 заполняется, вычислитель ожидает свободного места;
  ожидание может распространиться на читателя через Q1.

При 20 записях и задержке 50 мс на одном этапе каждый такой запуск
занимает примерно секунду или больше. Близкое общее время трёх режимов
ожидаемо: суммарная искусственная задержка одинаковая. Различается место
ожидания и заполнение очередей. Не нужно ожидать, что один режим
обязательно будет быстрее остальных.

Дополнительный режим 0 выполняет тот же конвейер без задержек.
После ввода 0 задержка не запрашивается: сразу вводите ёмкость 4.
Результат: output_normal.txt. Это необязательный контрольный запуск.

Что показывает консоль
- Число прочитанных, вычисленных и записанных задач. Для input.txt: 20/20/20.
- Задержки этапов.
- Максимальное заполнение Q1 и Q2.
- Сколько раз отправитель/получатель обнаружил заполненную/пустую очередь
  и обратился к ожиданию. Это не число уведомлений и не время ожидания;
  при пробуждении предикат проверяется повторно.
- Полное время конвейера: создание рабочих потоков, обработка, искусственные
  задержки, закрытие файлов рабочими потоками и join. Открытие файлов,
  создание очередей, ввод параметров и печать итогов в это время не входят.

Значения времени, ожиданий и заполнения зависят от планирования ОС.
Не требуется точное совпадение этих показателей с другим компьютером.
Все три выходных файла должны совпасть с expected_output.txt по содержимому.
Для отчёта снять консоль каждого из трёх запусков и показать входной
и выходные файлы. Задержки нужны для моделирования скоростей этапов,
а не для улучшения результата НОД.

АЛЬТЕРНАТИВНАЯ СБОРКА
CMake:
  cmake -S . -B build
  cmake --build build --config Release
Затем запустить полученный файл из папки, где находится input.txt,
либо в первом запросе указать полный путь к input.txt.

Linux / GCC:
  g++ -std=c++17 -O2 -Wall -Wextra -Wpedantic -pthread main.cpp -o lab2
  ./lab2

BOM, нули, ошибки формата, переполнение, отсутствие входа, ошибка записи
и защита от совпадения входного и выходного файлов.
